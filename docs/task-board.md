# TaskBoard

`TaskBoard`는 열·카드·구획(swimlane)을 편집하는 제어형 작업 보드입니다.
`@mega-ui/react`와 기본 `styles.css`에서 제공합니다. 추가 엔진 의존성은 없습니다.

```tsx
import { useState } from 'react';
import { TaskBoard, type TaskBoardData } from '@mega-ui/react';
import '@mega-ui/react/styles.css';

const initial: TaskBoardData = {
  version: 1,
  columns: [
    { id: 'todo', title: '할 일' },
    { id: 'doing', title: '진행 중', wipLimit: 3 },
  ],
  lanes: [{ id: 'product', title: '제품' }],
  assignees: [{ id: 'mega', name: '김메가' }],
  cards: [
    {
      id: 'task-1',
      title: '접근성 검토',
      columnId: 'todo',
      laneId: 'product',
      assigneeId: 'mega',
      dueDate: '2026-09-19',
    },
  ],
};
function Board() {
  const [value, setValue] = useState(initial);
  return <TaskBoard value={value} onChange={setValue} label="팀 작업 보드" />;
}
```

## API

| prop                        | 계약                                                                                                               |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| `value`                     | 필수 `TaskBoardData`. 원본을 변경하지 않음                                                                         |
| `onChange(next, action)`    | 편집·이동·실행 취소·복원의 결과. 부모에서 value를 갱신해야 반영. 생략 시 읽기 전용                                 |
| `onSave(snapshot)`          | 선택적 비동기 저장. resolve를 저장 확정으로 간주. 실패 시 현재 내용 유지. 실제 서버/브라우저 저장은 소비 앱이 수행 |
| `label`                     | 영역 이름·도구 제목. 기본 작업 보드                                                                                |
| `editable`                  | 기본 true. false는 CRUD를 숨기고 onChange가 있으면 이동은 허용                                                     |
| `allowReorder`              | 기본 true. false는 드래그·열/카드 순서 변경을 끄고 열 사이 이동 메뉴 유지. Kanban 호환용                           |
| `showTools`                 | 기본 true. 상단 편집/필터/저장/파일 도구 표시                                                                      |
| `renderCard(card)`          | 카드 본문을 ReactNode로 표현. 이동·편집 조작은 공통 구현을 유지                                                    |
| `renderColumnTitle(column)` | 열 제목을 ReactNode로 표현                                                                                         |
| 네이티브 div 속성           | ref·className·style·id·이벤트 전달. children/onChange 제외. 영역 role·이름은 보드가 지정                           |

`TaskBoardData`에는 `version: 1`과 다음 readonly 배열이 필요합니다.

- `columns`: `{id, title, wipLimit?: number}`. 배열 순서가 열 순서입니다.
- `cards`: `{id, title, description?, columnId, laneId?, assigneeId?, dueDate?}`. 배열 순서로 각 열/구획을 표시합니다.
- `lanes`: `{id, title}`. 생략할 구획은 카드의 laneId를 지정하지 않고, 빈 배열이면 구획 없는 보드입니다.
- `assignees`: `{id, name}`. 담당자 목록은 소비 앱이 제공합니다.

이름·ID는 최대 200 UTF-16 단위이며 공백만인 값은 거부합니다. 설명은 최대 5,000자입니다.
같은 종류의 ID 중복·없는 열/구획/담당자 참조·희소 배열·실제 달력에 없는 기한을 거부합니다.
기한은 `YYYY-MM-DD`의 날짜이며 시각·시간대 변환을 하지 않습니다.
최대 카드 1,000개·열 30개·구획 20개·담당자 100개·직렬화된 JSON 2백만 자입니다.

## 변경과 검증

`validateTaskBoard(unknown)`은 검증 후 알려진 필드만 복사한 데이터를 반환합니다.
`updateTaskBoard(value, action)`은 같은 검증을 사용하는 순수 함수입니다. 실패 시 예외를 던지며 원본은 유지됩니다.

`TaskBoardAction`:

- `put-card {card}`, `delete-card {id}`
- `move-card {id, columnId, laneId?, beforeId?}`: beforeId 앞에 삽입, 생략하면 전체 카드 배열 끝에 삽입. beforeId는 대상 열에 있어야 합니다.
- `put-column {column}`, `delete-column {id, toColumnId?}`
- `move-column {id, index}`: 제거 후 지정 위치에 열 삽입
- `put-lane {lane}`, `delete-lane {id}`

put은 같은 ID가 있으면 편집하고 없으면 추가합니다. 파일 교체·실행 취소의 onChange는 `{type: 'replace'}`를 전달합니다.

열의 WIP 제한은 필터·구획과 관계없이 열 전체 카드 수를 셉니다. 1~1,000의 정수이며 생략하면 제한하지 않습니다.
생성·이동·열 합치기·제한 변경·파일 반입 모두 같은 검증을 거칩니다. 제한을 넘기는 변경은 전체 취소합니다.
카드가 있는 열을 삭제할 때는 다른 열을 선택해야 합니다. 카드가 저절로 삭제되지 않습니다.
구획 삭제 시 카드는 미분류로 이동합니다. 카드·열·구획 삭제는 확인 화면을 거치며 적용 후 실행 취소가 가능합니다.

## 조작·접근성

- 마우스·펜으로 카드 본문이나 열 제목을 끌어 열 안/사이 순서, 구획, 열 순서를 바꿉니다. 버튼·링크·입력은 드래그를 시작하지 않습니다.
  터치는 이동 손잡이에서 시작하며 카드 본문에서는 기본 터치 스크롤을 유지합니다.
  이동 중 카드/열 이름과 목적지를 표시하고 WIP 제한에 도달한 열을 미리 알립니다. 삽입선은 카드 높이를 바꾸지 않습니다.
  보드 및 스크롤 가능한 상위 영역을 화면 경계에서 자동 스크롤합니다. Escape·창 포커스 이탈·pointercancel·유효하지 않은 위치에서 놓기는 이동을 취소합니다.
- 카드 손잡이에 포커스한 뒤 Alt+상하로 순서, Alt+좌우로 열을 바꿉니다. 열 손잡이는 Alt+좌우로 정렬합니다.
  상하 이동은 현재 필터와 구획 표시 상태에서 보이는 카드 순서를 따릅니다. 이동 후 손잡이 포커스를 복원하고 결과를 live region으로 알립니다.
- 카드의 네이티브 이동 메뉴로 위/아래·다른 열 끝·다른 구획을 선택할 수 있습니다.
  필터 결과에서 드래그해도 숨긴 카드는 지워지지 않습니다. 구획을 숨겼을 때의 드래그는 카드의 기존 구획을 유지합니다.
- 검색은 제목·설명의 부분 문자열, 담당자 필터는 ID, 기한 필터는 해당 날짜까지의 기한 있는 카드입니다.
  필터는 원본·저장·내보내기에 영향을 주지 않습니다. 열의 숫자는 항상 전체 카드 수입니다.
- Ctrl/Meta+Z, Shift+Ctrl/Meta+Z는 입력 필드 밖에서 보드의 실행 취소·다시 실행을 수행합니다.
  입력 필드의 브라우저 편집 기록과 한글 조합 키를 가로채지 않습니다.
- 다크·모바일·긴 문구를 기본 토큰으로 처리하고 가로 스크롤은 보드 내부에서만 발생합니다.
  그림에만 의존하는 드래그 대신 이동 메뉴와 키보드 대안을 제공합니다.

## 저장·복원

`onSave`가 있으면 저장 버튼을 제공합니다. 처음 입력은 기준 상태이며 실제 저장을 했다고 표시하지 않습니다.
처음 저장은 편집 없이도 가능합니다. 저장 호출은 중복 실행하지 않고, 실패하면 내용과 실행 취소 기록을 유지합니다.
저장 중 편집은 허용하며 저장 응답은 요청 당시 스냅샷만 확정합니다. 그 이후 편집은 저장하지 않은 변경으로 남습니다.
처음/저장한 상태로 복원하기와 파일 교체는 현재 보드 전체를 바꾸므로 적용 확인 화면을 제공합니다.
보드 ID가 바뀌거나 서버에서 완전히 다른 보드를 가져오면 미저장 변경을 처리한 뒤 React key로 재마운트하세요.

`serializeTaskBoard(data)`와 `parseTaskBoard(json)`으로 열·카드·구획·담당자·순서를 버전 1 JSON으로 왕복합니다.
알려지지 않은 필드는 보존하지 않습니다. 사용자 카드 렌더러의 JSX나 외부 메타데이터는 파일에 포함되지 않습니다.
파일 입력은 최대 8MB이며 파싱·검증에 실패하면 현재 보드에 적용하지 않습니다.
전체 보드 파일을 내려받고, 반입은 명시적으로 현재 보드 교체를 선택해야 반영합니다.
실행 취소 기록은 최대 50회이며 파일이나 저장 데이터에 포함하지 않습니다.
협업 서버·권한·충돌 버전 검증은 소비 앱 책임입니다. onSave 실패 시 서버의 원시 예외를 화면에 노출하지 않습니다.

## Kanban 통합과 예제

기존 `Kanban`의 독립 렌더링과 `.mega-kanban` 스타일은 제거했습니다.
`Kanban`/`KanbanCard`/`KanbanColumn`/`KanbanProps` export는 deprecated 호환 경로로 유지합니다.
기존 columns·ReactNode 제목/설명·onMove(cardId, from, to)는 TaskBoard에 위임합니다.
레거시 onMove에는 위치 정보가 없으므로 순서 편집을 제공하지 않습니다. 새 코드는 TaskBoard로 전환하세요.
기존 `.mega-kanban*`에 연결한 소비 앱 CSS는 `.mega-task-board*`로 옮겨야 합니다.

카탈로그는 **전문 업무 컴포넌트 → TaskBoard** 한 항목으로 통합했습니다.
Kanban 검색도 이 항목으로 연결합니다. 기존 `/#board?full=1` 프로젝트 보드 예제는 같은 TaskBoard 구현을 사용합니다.
이 예제는 localStorage에 실제 저장하고 저장본을 다시 불러옵니다. 파일 내려받기는 JSON으로 별도 제공하며
실패 재현 옵션은 저장 함수를 거부시킵니다. 데이터 예제를 전환하면 현재 예제 변경은 초기화됩니다.

## 검증 범위

- `tests/task-board.test.mjs`: CRUD·정렬·구획·WIP 원자성·원본 불변성·날짜·참조·상한·JSON·SSR·Kanban 위임.
- `tests/browser/task-board.spec.ts`: 편집·삭제 시 카드 보존·필터·실행 취소·저장 실패/재시도·저장 중 편집·재열기,
  실제 포인터 카드/열 정렬·키보드 이동·취소·파일 반입/반출·다크 모바일·검색 통합.
  1280×720 기본 구획 화면의 카드 본문 드래그·하단 구획 자동 스크롤·WIP 드롭 거부·구획 숨김 키보드 정렬을 별도로 검사합니다.
- 성능 기준: 500카드(네 열·두 구획)의 예제 전환 후 DOM 표시 1,500ms 미만. 브라우저 개발 서버에서 측정하며
  최초 네트워크 로딩을 포함하지 않습니다. 같은 데이터의 키보드 열 이동은 800ms 미만을 기준으로 검사합니다. 최대 1,000카드를 지원하지만 가상화는 하지 않습니다.
- Chromium에서는 CDP 터치 입력을 별도로 검사합니다. 실제 OS IME·모바일 하드웨어·스크린 리더 낭독은 수동 검증하지 않았습니다.

### 실행 기록 · 2026-09-09

Node 24.18.0, macOS arm64, Playwright의 Chromium·Firefox·WebKit, Vite 개발 서버, 2 workers.
500개 카드의 단일 예제 전환/키보드 이동 측정은 각각 Chromium 500/209ms, Firefox 672/223ms, WebKit 212/140ms였습니다.
통계적 벤치마크나 실제 기기 성능 보장은 아닙니다.
다크 390px·데스크톱 화면과 문구를 검토했습니다. 전체 카드 제한, 파일 교체 범위, 구획 삭제 후 카드 위치,
저장 실패 시 내용 보존과 실제 저장 완료 뒤의 상태 문구를 동작과 대조했습니다.

### DnD 재점검 · 2026-09-09

기존 검사는 이동 손잡이와 넓은 화면 중심이어서 카드 본문 드래그 실패를 놓쳤습니다.
1280×720 기본 화면에서 실패를 재현한 뒤 본문/열 제목 드래그, 목적지 미리보기와 WIP 안내,
레이아웃을 바꾸지 않는 삽입선, 화면 밖 구획을 향한 자동 스크롤을 보완했습니다.
드래그 중 Escape는 창에서 처리하고, 본문 텍스트 선택과 드래그가 충돌하지 않도록 처리합니다.
Safari에서 텍스트 선택의 자동 스크롤 때문에 출발 위치로 돌아가던 현상을 방지합니다.
구획을 숨겼을 때 키보드 상하 이동도 보이는 순서를 따릅니다. 예제 설정은 보드 아래로 이동했습니다.

문구 의미 검토: 미리보기는 이동 예정 위치만 안내하며, 제한을 초과한 드롭은 원본을 유지하고 다른 열 선택/제한 변경을 안내합니다.
터치 안내는 실제로 드래그를 시작할 수 있는 손잡이를 명시합니다. 이동·취소·실행 취소 문구를 각각의 결과와 대조했습니다.
실제 모바일 하드웨어와 스크린 리더 낭독은 이 재점검에 포함하지 않았습니다.
