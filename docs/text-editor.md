# TextEditor

`@mega-ui/react/text-editor`의 전문 문서 편집기입니다. 로드맵의 문단·서식·목록·링크·표·이미지·블록 편집,
Markdown 변환, 붙여넣기 정제, undo/redo, 문서 저장·복원을 구현했습니다.
한글 조합은 엔진 처리와 자동 회귀 검사를 제공하며, 실제 OS 입력기·보조 기술 수동 검증은 별도입니다.

React 19용 Tiptap 3.31.3(MIT)을 사용하며 기본 진입점에 편집 엔진을 포함하지 않습니다.
CSS와 엔진은 편집기를 사용하는 화면에서 로드합니다.

```tsx
import {
  TextEditor,
  serializeTextEditorDocument,
} from '@mega-ui/react/text-editor';
import '@mega-ui/react/styles.css';
import '@mega-ui/react/text-editor.css';

<TextEditor
  label="운영 문서 본문"
  onSave={async (document) => {
    const response = await fetch('/api/document', {
      method: 'PUT',
      headers: { 'Content-Type': 'application/json' },
      body: serializeTextEditorDocument(document),
    });
    if (!response.ok) throw new Error('Save rejected');
  }}
/>;
```

## API와 상태 소유권

| API                                     | 계약                                                                                                                                                                               |
| --------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `label: string`                         | section과 편집 영역의 접근 가능한 이름. 필수입니다.                                                                                                                                |
| `defaultValue?: TextEditorDocument`     | 최초 JSON 문서. 기본은 빈 문단입니다. 이후 편집 상태는 컴포넌트가 소유합니다. 외부 문서 교체·변경 취소는 확인 후 `key`로 재마운트합니다. prop 변경만으로 입력을 덮어쓰지 않습니다. |
| `readOnly?: boolean`                    | 편집·붙여넣기·서식·표 크기 조절·저장을 막고 내보내기는 유지합니다. 전환 중 초안과 undo 이력은 유지합니다. 이미 시작한 저장은 완료될 수 있습니다.                                   |
| `onChange?(document)`                   | 변경된 JSON 문서 알림. 저장 완료를 의미하지 않습니다. 앱 내부 이동 보호에 연결합니다.                                                                                              |
| `onSave?(document): Promise<void>`      | 전달된 문서를 확정한 뒤 resolve, 실패 시 reject합니다. 없으면 저장 버튼을 제공하지 않습니다.                                                                                       |
| `ref`, `className`, section 속성        | 바깥 section에 전달합니다. ref는 편집기 인스턴스가 아닙니다.                                                                                                                       |
| `serializeTextEditorDocument(document)` | `{ version: 1, document }` JSON 문자열. 스키마·링크·이미지·표를 검사합니다.                                                                                                        |
| `parseTextEditorDocument(text)`         | 같은 버전의 문서를 검증·정규화합니다. 손상·미지원 노드·위험 주소·크기 초과는 예외를 던집니다.                                                                                      |
| `parseTextEditorMarkdown(text)`         | Markdown을 검증된 JSON 문서로 변환합니다. 지원 문법과 변환 제약은 아래와 같습니다.                                                                                                 |
| `exportTextEditorMarkdown(document)`    | `{ markdown: string, warnings: string[] }`를 반환합니다. 원본은 바꾸지 않습니다. 경고를 사용자에게 먼저 표시합니다.                                                                |

`TextEditorDocument`는 Tiptap `JSONContent` 타입이며 타입만으로 외부 입력을 보장하지 않습니다.
외부 문서는 `parseTextEditorDocument`로 먼저 검사하고 실패하면 원본을 보존하는 오류 화면을 제공합니다.
초깃값 검증 실패는 예외이므로 소비 앱에서 처리해야 합니다.

저장 중 편집을 잠그고 중복 저장을 막습니다. 실패하면 입력과 이력을 유지하며 재시도할 수 있습니다.
성공 안내는 `onSave`가 resolve한 뒤 표시합니다. 서버 권한·버전 충돌·원자적 저장은 소비 앱 책임입니다.
미저장 변경에 `beforeunload` 경고를 등록하지만 강제 종료나 앱 내부 라우팅을 보장하지 않습니다.
자동 초안 보관·협업·서버는 내장하지 않습니다. 저장 전 언마운트하면 입력과 이력이 사라집니다.

## 편집 화면

본문을 중앙에 두고 상단에 저장 상태와 저장 버튼, 짧은 서식 툴바를 제공합니다.
문단 종류는 드롭다운, 기본 서식은 B/I/U 등의 버튼이며 전체 행동 이름을 접근 가능한 이름과 title로 제공합니다.
링크·추가 서식·표·이미지·블록·파일 메뉴는 한 번에 하나의 도구 패널을 엽니다.
데스크톱에서는 본문 옆에, 좁은 화면에서는 본문 위에 패널을 표시합니다. 닫기 또는 Escape로 닫고 메뉴로 포커스를 돌립니다.
도구를 전환해도 편집기와 문서를 재마운트하지 않습니다. 예제의 실패 시뮬레이션·읽기 전용·변경 취소는 하단 `예제 옵션`에 있습니다.

**표 선택:** 셀을 드래그해 범위를 선택합니다. 키보드는 셀 안에서 `표 전체 선택` 후 병합할 수 있습니다.
Tab/Shift+Tab으로 셀을 이동합니다. 병합 셀의 너비 입력은 셀에 걸친 각 열에 적용합니다.
행 높이는 24~4,096px이며 빈 값으로 적용하면 자동 높이로 돌아갑니다. 선택 범위에 걸친 행에 적용하고, `표 전체 선택` 후에는 모든 행에 적용합니다.
내용이 많으면 지정한 높이보다 늘어납니다. 행 아래쪽 경계를 마우스로 드래그하고 Escape로 취소할 수 있습니다. 높이는 JSON 저장·복원과 undo/redo에 포함되며 Markdown에서는 제외됩니다.
열 너비 변경 중 엔진이 다른 행의 너비를 맞추는 중간 상태는 허용하고, 충돌·누락·범위 초과 구조는 거부합니다.
표와 목록은 블록 순서 패널에서 한 단위로 이동하며, 내부 항목은 편집기에서 편집합니다.
블록 삭제는 확인 대화상자 없이 실행하며 undo로 복원합니다.

**이미지:** 파일 선택은 업로드가 아니라 문서에 포함할 data URL 준비입니다. 설명 또는 장식용 여부를 정한 뒤 `이미지 추가`를 누릅니다.
이미지를 선택하고 `선택 이미지 정보 불러오기`로 필드를 채운 뒤 수정합니다. 너비를 비우면 원본 비율로 표시합니다.
삽입한 파일은 JSON 안에 포함되어 재열기 후에도 유지됩니다. 외부 URL은 원본 서비스의 이용 가능성에 의존합니다.
붙여넣은 이미지에 설명이 없으면 `설명 없는 이미지`로 식별하며, 소비자가 내용을 설명하는 대체 텍스트로 수정해야 합니다.

## 입력·변환의 경계

- 문서 JSON/Markdown은 최대 1,000,000 UTF-16 코드 단위입니다. 파일 선택 단계에서 4MB를 넘는 문서는 미리 거부합니다.
  편집 중 상한을 넘으면 잘라내지 않고 저장/내보내기를 거부합니다. 현재 화면의 내용은 유지됩니다.
- 이미지 파일은 512,000바이트 이하 PNG·JPEG·GIF·WebP만 지원합니다. MIME·바이너리 헤더·브라우저 디코딩을 확인합니다.
  이미지 data URL은 같은 형식과 크기를 검사합니다. SVG·blob·file·상대 주소는 지원하지 않습니다.
  여러 파일을 포함하면 문서 전체 크기 상한에 먼저 도달할 수 있습니다. 이미지 크기는 1~4,096px입니다.
- 링크는 공백·제어문자가 없는 절대 http/https/mailto/tel, 이미지 URL은 http/https만 허용합니다.
  링크 클릭은 편집기 밖으로 이동하지 않습니다. 이미지 요청에는 referrer를 보내지 않습니다.
- 표는 최대 100행·100열, 문서 전체 최대 10,000셀입니다. 병합 범위·열 너비·표의 겹침과 누락을 검증합니다.
- JSON은 스키마 밖의 속성을 보존하지 않을 수 있습니다. 원본 HTML 보관이나 임의 HTML 렌더링 API가 아닙니다.
  붙여넣기에서 지원하지 않는 Word 스타일 등은 제거될 수 있습니다.

### Markdown 문법과 손실 안내

CommonMark 기반 문단·제목·링크·이미지·코드·인용·목록과 GFM 표·취소선을 지원합니다.
밑줄은 Tiptap의 `++글자++` 확장 문법이며 다른 Markdown 도구에서는 그대로 표시될 수 있습니다.
병합 셀·열 너비·행 높이·셀 안의 여러 문단/블록·이미지 크기는 Markdown만으로 원래 형태를 유지하지 못합니다.
제목 행이 없는 표는 첫 행이 제목 행으로 바뀝니다. 해당 경우 `warnings`와 UI 안내를 먼저 제공합니다.
원본의 구조·크기를 보관하려면 JSON 내보내기를 사용합니다. Markdown 다운로드는 현재 편집 문서를 바꾸지 않습니다.

브라우저에서 Markdown 안의 HTML은 엔진 스키마로 정제해 파싱합니다. Node 환경에서는 HTML 토큰이 문자로 보존될 수 있습니다.
서버/브라우저에서 같은 결과가 필요하면 Markdown 문법만 사용하세요. 외부 파일 원문은 변환 결과와 별도로 보관하는 것이 좋습니다.
엔진의 Markdown 모듈은 upstream beta이므로 버전은 3.31.3으로 고정하고 업데이트 시 왕복 검사를 재실행합니다.

## 예제와 검사

`/#text-editor?full=1`: 운영 문서 편집 → 브라우저 저장 → 새로고침 → 복원 흐름입니다.
표/이미지/블록 도구와 문서 반입/반출을 사용하고, 저장 실패 시뮬레이션·읽기 전용·변경 취소를 확인할 수 있습니다.
손상된 보관 자료를 자동 삭제하거나 덮어쓰지 않습니다. 실제 서버 저장 예제는 아닙니다.

```sh
npm run check
npm run test:browser -- tests/browser/text-editor.spec.ts tests/browser/text-editor-advanced.spec.ts
```

성능 기준: 1,000문단(각 약 40자)의 새로고침부터 표시까지 3초 이내, 마지막 문단 접근·입력 표시까지 3초 이내.
개발 서버에서 측정하며 대형 문서·장시간 편집의 성능 보장이 아닙니다.
실제 OS IME·스크린 리더·실물 터치 기기·실제 서버 저장은 수동 검증이 남습니다.
브라우저의 합성 IME·터치 이벤트를 실기기 검증 완료로 표시하지 않습니다.
