# Mega UI 문서 사이트 UI 점검 리포트 (2026-09-09)

- 범위: 1440px 데스크톱 전 페이지 39개 · 다크 모드 8개 · 390px 모바일 7개
- 방법: 헤드리스 Chrome 전체 페이지 캡처 후 1200px 단위로 잘라 육안 검토. 모바일은 390px iframe으로 실제 레이아웃 측정.
- 최초 결과: 총 54건 — P0 6건 · P1 38건 · P2 10건
- 재점검: 54건 수정 완료. 아래 문제 설명은 수정 전 기록이며 체크 상태는 재검증 결과입니다.

P0는 깨짐·잘림·동작 오류, P1은 눈에 띄는 품질 문제, P2는 마감. 각 항목은 위치 → 문제 → 개선 방법 순서입니다.

## P0 · 즉시 수정 (깨짐·잘림·동작 오류)

- [x] **P0-1** · 컴포넌트 › 버튼·컨트롤 › Button
  - 문제: 로딩 상태에서 점 스피너가 라벨 위에 겹쳐 「••처리 중」으로 보임.
  - 개선: 스피너를 라벨과 별도 flex 아이템으로 두고 gap 6px. 로딩 중에는 라벨을 숨기거나 버튼 min-width를 로딩 전 너비로 고정해 레이아웃 점프를 막기.
- [x] **P0-2** · 화면 예제 › 회원가입 (Stepper)
  - 문제: 단계 라벨이 글자 단위로 줄바꿈됨. 데스크톱 「정보 입/력」「휴대폰/인증」, 390px에서는 세로로 한 글자씩 떨어짐.
  - 개선: 라벨에 `white-space: nowrap; word-break: keep-all`. 폭이 부족하면 현재 단계만 라벨을 보여주고 나머지는 번호만 남기는 compact 모드(예: 「2/4 정보 입력」)로 전환.
- [x] **P0-3** · 컴포넌트 › 업무·대용량 데이터 › EditableTable
  - 문제: 이름 셀이 「김메/가」「이하/늘」처럼 단어 중간에서 끊김.
  - 개선: 텍스트 열에 `white-space: nowrap` + `min-width: 72px`, 입력 열은 `width: 100%`로 나머지 폭을 나눠 갖게. 한글은 항상 `word-break: keep-all`.
- [x] **P0-4** · 컴포넌트 › 업무·대용량 데이터 (Kanban·Gantt·Spreadsheet·VirtualTable) / 기초·레이아웃 확장 › ScrollArea
  - 문제: 오른쪽·아래가 카드 경계에서 그냥 잘림. 가로 스크롤 가능 여부나 더 있다는 신호가 전혀 없음. VirtualTable·ScrollArea는 행이 글자 중간에서 반쯤 잘려 렌더링 버그처럼 보임.
  - 개선: 각 데모를 `overflow: auto` 컨테이너로 감싸고 테두리 + 오른쪽/아래 gradient fade(마스크)로 이어짐을 표시. 고정 높이 리스트는 행 높이의 정수배로 높이를 맞추기.
- [x] **P0-5** · 소개(홈) › 3분 만에 시작하기 › 2. 사용
  - 문제: 코드 블록이 카드 밖으로 넘쳐 「fr」「</Text」처럼 잘림. 390px에서는 618px 폭까지 넘침(측정).
  - 개선: `pre`에 `overflow-x: auto`, 모바일은 `white-space: pre-wrap`. import 한 줄이 너무 길면 두 줄로 나누기.
- [x] **P0-6** · 전체 › 다크 모드 토글
  - 문제: 새로고침하면 라이트로 되돌아가고 OS 다크 설정도 무시함(App.tsx `useState(false)`, 저장·매체쿼리 없음).
  - 개선: 초기값 = localStorage → `matchMedia('(prefers-color-scheme: dark)')` 순. 토글 시 저장하고 `<html>`에 `color-scheme`도 함께 지정해 네이티브 컨트롤·스크롤바까지 맞추기.

## P1 · 문서 사이트 셸 (모든 페이지에 반복되는 문제)

- [x] **P1-1** · 컴포넌트 카테고리 12페이지 전체
  - 문제: 2열 그리드가 행 높이로 카드를 늘려서 짧은 카드(Container, Textarea, IconButton, Spinner, AvatarGroup, Scheduler 등)에 300~600px 빈 공간이 생김. 사이트 전체에서 가장 자주 눈에 띄는 어색함.
  - 개선: `.docs-grid { align-items: start }` 한 줄. 더 좋게는 예상 높이가 비슷한 카드끼리 짝짓거나 긴 카드(Input, 데이터 테이블)는 `grid-column: 1 / -1`로 한 줄 차지.
- [x] **P1-2** · 화면 예제 전체
  - 문제: 문서 제목 + 설명 바로 아래 예제 화면의 제목 + 설명이 또 나와 제목이 두 번 쌓임(자산 홈: 「내 자산을 한눈에, 금융 홈.」→「내 돈, 한눈에 모아보기」). 어디까지가 문서고 어디부터가 예제인지 경계가 없음.
  - 개선: 예제를 미리보기 프레임(연한 도트 배경 + 1px 테두리 + 상단에 「미리보기 · 데스크톱」 툴바)에 넣어 문서 크롬과 시각적으로 분리. 문서 설명은 breadcrumb 아래 한 줄 eyebrow로 축소.
- [x] **P1-3** · 화면 예제 전체 › 「예제 소스 코드 보기」
  - 문제: 네이티브 details 토글이 예제 안의 아코디언(카드 관리 FAQ, 랜딩 FAQ, 회원가입 약관)과 똑같이 생겨 예제의 일부로 읽힘.
  - 개선: 위 미리보기 프레임 툴바에 「미리보기 | 코드」 탭 또는 secondary 버튼으로 이동. 언어 표시(React · TypeScript)는 Badge로.
- [x] **P1-4** · 전체 › 푸터
  - 문제: 푸터 텍스트 시작점이 x=272로 본문 컬럼(x=296)보다 24px 왼쪽에 있어 정렬이 어긋남. 모든 일반 폭 페이지에서 반복.
  - 개선: `.docs-footer`를 본문과 같은 컨테이너/패딩 안에 두기.
- [x] **P1-5** · 전체 폭(wide) 예제 7개 (증권 홈, 어드민 등)
  - 문제: 일반 페이지와 제목 여백이 다르고(272 vs 296) 헤더 밴드에만 하단 선이 있어 페이지마다 헤더가 달라 보임.
  - 개선: 페이지 헤더는 항상 같은 패딩·정렬. wide는 예제 영역만 넓히기.
- [x] **P1-6** · 전체 › 사이드바
  - 문제: 고정(sticky)되지 않아 긴 페이지에서 스크롤하면 왼쪽이 빈 흰 기둥만 남음. 카테고리 페이지 하단에서 특히 두드러짐.
  - 개선: `position: sticky; top: 60px; max-height: calc(100vh - 60px); overflow-y: auto`.
- [x] **P1-7** · 화면 예제 갤러리
  - 문제: ①「전체 너비」배지는 내부 플래그(wide)가 사용자에게 노출된 것. ②섹션마다 열 수가 4→3으로 바뀌어 카드 폭이 달라짐. ③제목 끝 마침표가 「결/제.」「가/입.」처럼 혼자 떨어짐. ④카드 전체가 아니라 작은 「화면 열기」만 클릭됨.
  - 개선: 배지 제거(또는 데스크톱/모바일 아이콘). 열 수 `repeat(4, minmax(0,1fr))` 고정. 제목 마침표 제거 + `word-break: keep-all; text-wrap: balance`. 카드 전체를 링크로, hover 시 살짝 떠오름.
- [x] **P1-8** · 소개(홈)
  - 문제: 화면 예제 그룹 카드 5개가 4열에 놓여 하나가 외톨이. 「모든 화면 예제 보기 · 25개」가 화면 폭 전체 회색 막대라 비활성 배너처럼 보임.
  - 개선: 그룹 카드는 5열 또는 3+2 균등 폭. 「모든 화면 예제 보기」는 섹션 제목 오른쪽의 텍스트 링크(→)로.
- [x] **P1-9** · 컴포넌트 카테고리 상단 칩 목록
  - 문제: 컴포넌트 이름 칩이 태그처럼 보여 눌러도 되는지 알 수 없음. 현재 위치 표시도 없음.
  - 개선: 앵커 링크 스타일(hover 밑줄, 선택 시 brand 배경)로 바꾸고 스크롤에 따라 active 표시.
- [x] **P1-10** · 컴포넌트 카테고리 › 데모 트리거 버튼
  - 문제: 「열기」류 버튼 스타일이 페이지마다 다름. 탐색·오버레이 확장은 전부 전체 폭 primary(삭제 확인은 전체 폭 빨강), 콘텐츠·파일·AI는 전체 폭 secondary, 오버레이는 작은 primary.
  - 개선: 규칙 하나: 데모 트리거 = size md · secondary · 인라인(전체 폭 금지). destructive는 AlertDialog에만, 그것도 인라인.

## P1 · 화면 예제 25개

- [x] **P1-11** · 대출 계산기
  - 문제: 왼쪽 입력 카드 내용은 670px에서 끝나는데 카드는 오른쪽 결과 카드 높이(975px)까지 늘어나 아래 300px이 비어 있음. 상환 방식 라디오 3개가 2+1로 불규칙하게 줄바꿈.
  - 개선: 2열 그리드에 `align-items: start`. 라디오는 세로 스택.
- [x] **P1-12** · 카드 관리
  - 문제: 카드 이미지가 왼쪽에 혼자 떠 있고 오른쪽 60%가 빈 공간. 혜택 배지 4개가 전부 「혜택」인데 색만 파랑·초록·보라·주황으로 달라 색이 아무 의미도 전달하지 않음.
  - 개선: 히어로를 2열로: 카드 이미지 | 카드명·이번 달 혜택·상태·CTA(분실 신고). 배지 텍스트를 카테고리(카페/교통/구독/해외)로 바꾸면 색 구분이 의미를 얻음.
- [x] **P1-13** · 알림센터
  - 문제: 「확인」액션이 카드 하단 가운데에 떠 있음. 읽은 알림의 「읽음」텍스트가 배경과 거의 같은 색이라 보이지 않음. 읽은 항목도 색 틴트를 옅게 유지해 안 읽은 것과 구분이 약함.
  - 개선: 카드를 row 레이아웃으로 바꿔 액션을 오른쪽 끝 세로 중앙에. 읽은 항목은 틴트 없는 기본 surface + muted 텍스트, 「읽음」라벨은 제거하거나 체크 아이콘.
- [x] **P1-14** · 소비 리포트
  - 문제: 기간 선택이 pill 탭인데 자산 홈의 같은 기능은 SegmentedControl. 3번째 통계 카드(도넛)만 세로 중앙 정렬이라 1·2번과 시선이 어긋남. 「하루 평균」카드 하단이 비어 있음.
  - 개선: 같은 의도 = 같은 컨트롤(SegmentedControl). 통계 카드 3개 모두 상단 정렬, 도넛은 숫자 오른쪽에 작게.
- [x] **P1-15** · 사용자 관리
  - 문제: 숫자 열(로그인 횟수)이 왼쪽 정렬. 「전체」셀렉트와 「모두/활성/비활성」칩이 나란히 있어 '전체'가 둘로 보임.
  - 개선: 숫자 열 오른쪽 정렬 + `tabular-nums`. 셀렉트에 필드 라벨 「역할: 전체」.
- [x] **P1-16** · 프로젝트 보드
  - 문제: 카드 이동 버튼이 텍스트 화살표 「←」「→」라 아이콘 세트와 어울리지 않고 플레이스홀더처럼 보임.
  - 개선: IconButton(chevron-left/right) 또는 「이동…」메뉴. 이상적으로는 드래그 핸들.
- [x] **P1-17** · 보안·기기 / 주문 상세 / Timeline 컴포넌트
  - 문제: 활동 기록이 「1. 2. 3.」번호와 타임라인 선을 동시에 써서 목록인지 타임라인인지 애매함. 순서가 정보가 아닌 곳에 번호를 붙임. 2단계 인증 카드는 「꺼짐」배지와 토글이 같은 상태를 두 번 말함.
  - 개선: Timeline은 점 + 선만. 번호는 실제 절차(송금 3단계)에만. 2FA 배지는 제거하고 라벨 아래 상태 문구로.

  - 문제: 설명은 「스트리밍 답변, 작업 상태」를 약속하지만 화면엔 메시지 1개와 빈 공간뿐. 채팅 영역의 절반이 비어 있음.

### 적용 범위

날짜·시간·색상·파일 입력은 네이티브 동작을 유지하며 아이콘·선택 상태·버튼을 정리했습니다. OTP는 시각적인 칸과 단일 네이티브 입력을 함께 사용해 붙여넣기와 자동 완성을 유지합니다. Textarea 자동 높이는 `field-sizing` 지원 브라우저에서 적용되며, 다른 브라우저에서는 정해진 높이 안에서 스크롤합니다. 캐러셀은 터치 스와이프와 버튼을 지원하고 마우스 드래그는 추가하지 않았습니다.

Safari·Firefox·스크린 리더 전수 검사는 수행하지 않았습니다. 문서 사이트 번들의 500KB 초과 경고는 남아 있으며 빌드는 성공했습니다. 별칭 통합은 기존 API를 유지하며 교차 링크와 로드맵으로 정리했습니다.
